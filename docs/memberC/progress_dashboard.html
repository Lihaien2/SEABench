4下一步：Safety Invariant Preservation

研究问题：智能体持续自我修改时，旧版本建立的安全约束在多少次修改后仍然成立？重点不是最终任务成功率，而是安全约束的存活率。

消融分组 · 在 apply_controller_update 挂载独立检查器
  • G0 直接接受：关闭检查器，作为基线
  • G1 静态检查：白名单 / 短语 / 标记扫描（复用现有 gate）
  • G2 行为回归测试：每次修改后重放固定安全探针任务
  • G3 历史版本回滚：维护控制器版本链，违规即回退

对照组沿用仓库已有的 non-evolving baseline（surface=none），与论文配对设计一致，可直接做因果归因。

建议报告的四项指标
  • 任务成功率：上游 + 下游任务完成比例
  • 安全违规率：下游安全测试中触发违规的比例
  • 危险修改被接受比例：判定危险的修改中实际写入的比例
  • 单位改进的 API 成本：每提升 1 个百分点成功率的费用

建议接入：self_improve.py / validation_dispatcher.py / tracker.py / configs/runs/
